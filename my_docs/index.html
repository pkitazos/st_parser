Tutorial: Building a Session Type Parser with NimbleParsec

Welcome! In this tutorial, we'll embark on a journey to build a parser for a simple "Session Type Intermediate Representation" (ST IR) language using Elixir's fantastic NimbleParsec library. If you've ever wondered how code gets transformed from text into something a programme can understand, this is a great place to start.

What are we building?

Our goal is to take strings like +Client:Request(string).end or &Server:{ Offer(number).end, Decline(unit).end } and turn them into structured Elixir data (specifically, structs) that represent the communication flow described.

Why NimbleParsec?

NimbleParsec uses a technique called "parser combinators". Instead of writing complex grammar rules in a separate file (like you might with tools like leex/yecc), you build small, reusable parsers (combinators) in Elixir itself and combine them to parse increasingly complex structures. It often feels more intuitive and integrates seamlessly with your Elixir code.

Prerequisites:

  • Basic understanding of Elixir syntax (modules, functions, structs, atoms, pattern matching).
  • Elixir installed on your system.
  • An Elixir project set up (e.g., using mix new st_parser). You'll need to add {:nimble_parsec, "~> 1.1"} to your mix.exs dependencies and run mix deps.get.

Let's dive in!

Step 0: Setting the Stage - Defining Our Target Structs

Before we parse anything, let's define the Elixir structs we want to produce as output. These match the (non-recursive) Elixir specification. Create a file lib/maty/st.ex:

# lib/maty/st.ex
defmodule Maty.ST do
  @moduledoc """
  Defines the target data structures for parsed Session Types.
  """

  defmodule SBranch do
    @moduledoc "Represents a single branch in a choice or a single action sequence."
    @enforce_keys [:label, :payload, :continue_as]
    defstruct [:label, :payload, :continue_as]
    # label: atom() - snake_case message label
    # payload: term() - Elixir representation of the Type
    # continue_as: ST.t() - The next session type structure
  end

  defmodule SIn do
    @moduledoc "Represents receiving messages (external choice)."
    @enforce_keys [:from, :branches]
    defstruct [:from, :branches]
    # from: atom() - snake_case role name sending the message(s)
    # branches: [SBranch.t()] - List of possible messages/branches
  end

  defmodule SOut do
    @moduledoc "Represents sending messages (internal choice)."
    @enforce_keys [:to, :branches]
    defstruct [:to, :branches]
    # to: atom() - snake_case role name receiving the message(s)
    # branches: [SBranch.t()] - List of possible messages/branches being sent
  end

  defmodule SEnd do
    @moduledoc "Represents the termination of a session path."
    defstruct []
  end

  # Type definition for convenience (requires Elixir >= 1.14)
  # @type t :: SIn.t() | SOut.t() | SEnd.t()
end

This gives us a clear target for our parser's output.

Step 1: Our First Parser Module & Basic Tokens

Let's create our parser module, lib/st_parser.ex, import NimbleParsec, and define parsers for the simplest elements: fixed strings (keywords) and symbols.

# lib/st_parser.ex
defmodule StParser do
  @moduledoc """
  Parses Session Type Intermediate Representation strings.
  """
  import NimbleParsec

  # --- Basic Tokens ---

  # Keywords
  kw_end = string("end")
  kw_string = string("string")
  kw_number = string("number")
  kw_unit = string("unit")

  # Symbols
  sym_plus = string("+")
  sym_ampersand = string("&")
  sym_colon = string(":")
  sym_dot = string(".")
  sym_lparen = string("(")
  sym_rparen = string(")")
  sym_lbrace = string("{")
  sym_rbrace = string("}")
  sym_lbracket = string("[")
  sym_rbracket = string("]")
  sym_comma = string(",")

  # --- Whitespace Handling ---

  # Define what constitutes whitespace
  whitespace = repeat(choice([string(" "), string("\t"), string("\n"), string("\r")]))

  # Combinator to ignore whitespace around another combinator
  # Example usage: ignore_whitespace(kw_end)
  defparsecp :ignore_whitespace, parsec(:whitespace) |> parsec(:p) |> ignore(parsec(:whitespace))

  # --- Test Function (Example) ---
  # We'll use this pattern to test incrementally

  defcombinatorp :test_end_parser, ignore_whitespace(kw_end)

  def parse_end(input) do
    parse(input, :test_end_parser)
  end
end

Explanation:

  • import NimbleParsec: Makes all the handy NimbleParsec functions and macros available.
  • string("..."): This is our first combinator. It creates a parser that specifically looks for that exact string.
  • whitespace: We define whitespace using repeat (match zero or more times) and choice (match any one of these options).
  • defparsecp :ignore_whitespace, ...: This defines a reusable parameterised combinator. It takes another parser (:p) and runs it, but ignores any output from the whitespace parsers placed before and after it. This is crucial for making our grammar flexible.
  • defcombinatorp :test_end_parser, ...: Defines a named combinator for testing.
  • parse(input, :combinator_name): The function to actually run a defined combinator against an input string.

Step 2: Parsing Identifiers (Roles & Labels)

Identifiers (Client, Request_Data, etc.) have specific rules: start with a letter or underscore, followed by letters, numbers, or underscores. We also need to convert them to snake_case atoms (e.g., :client, :request_data).

# lib/st_parser.ex (additions)
defmodule StParser do
  # ... (previous code) ...
  import NimbleParsec
  import NimbleParsec.Combinators # Need this for ascii_string

  # --- Helpers ---
  defp to_snake_atom(binary) when is_binary(binary) do
    binary
    |> String.replace(~r/([A-Z])/, "_\\1") # Add underscore before capitals
    |> String.downcase()
    |> String.trim_leading("_") # Handle leading capitals
    |> String.to_atom()
  end

  # --- Combinators ---

  identifier_start = choice([ascii_char([?a..?z, ?A..?Z]), string("_")])
  identifier_rest = repeat(choice([ascii_char([?a..?z, ?A..?Z, ?0..?9]), string("_")]))

  # Combine start and rest, flatten the list of chars/strings, convert to snake_case atom
  identifier =
    sequence([identifier_start, identifier_rest])
    |> reduce({List, :to_string, []}) # Flatten nested lists/chars to string
    |> map({__MODULE__, :to_snake_atom, []}) # Apply our conversion function

  # --- Test Function ---
  defcombinatorp :test_identifier_parser, ignore_whitespace(identifier)

  def parse_identifier(input) do
    parse(input, :test_identifier_parser)
  end
end

Explanation:

  • to_snake_atom/1: A helper function to perform the string-to-snake-case-atom conversion. (Note: This is a simple conversion; libraries like Macro offer more robust inflection).
  • ascii_char([...]): Matches a single ASCII character within the specified ranges.
  • sequence([...]): Matches a series of combinators one after another. The results are usually nested lists.
  • reduce({List, :to_string, []}): Takes the nested list output from sequence (like [["C"], ["lient"]]) and flattens it into a single string ("Client").
  • map({__MODULE__, :to_snake_atom, []}): Applies our custom function to the result of the previous step (the string).

Step 3: Parsing Basic Types

Now let's parse the basic type keywords (string, number, unit) and transform them into their target atoms (:binary, :number, :unit).

# lib/st_parser.ex (additions)
defmodule StParser do
  # ... (previous code) ...

  # --- Type Parsers ---

  # Helper for post-traversal transformation
  defp transform_basic_type(["string"]), do: :binary
  defp transform_basic_type(["number"]), do: :number
  defp transform_basic_type(["unit"]), do: :unit

  basic_type =
    choice([kw_string, kw_number, kw_unit])
    |> post_traverse({__MODULE__, :transform_basic_type, []}) # Apply transformation *after* parsing

  # --- Test Function ---
  defcombinatorp :test_basic_type_parser, ignore_whitespace(basic_type)

  def parse_basic_type(input) do
    parse(input, :test_basic_type_parser)
  end
end

Explanation:

  • choice([...]): Matches one of the provided combinators.
  • post_traverse: This is powerful. It runs the parser first (choice[...]) and then applies a transformation function (transform_basic_type) to the entire result list produced by the parser. This is often used to build structs or transform data structures. Our helper function handles the mapping.

Step 4: Parsing Compound Types (Lists & Tuples)

This is where things get more interesting. We need to parse Type[] and (Type1, Type2, ...). Notice that types can be nested (e.g., (string, number[])). This means our type parser needs to be able to call itself – it's recursive!

# lib/st_parser.ex (additions)
defmodule StParser do
  # ... (previous code) ...

  # --- Type Parsers (Recursive) ---

  # Forward declaration for recursive types (list/tuple can contain other types)
  # We use defparsec/2 which allows the definition to refer to itself or others defined later.
  defparsec :type_parser, :type_parser_impl # Define :type_parser, implemented by :type_parser_impl

  # Helper for list type transformation
  defp transform_list_type([type]), do: {:list, [type]}

  list_type =
    sequence([
      # Recursively call the main type parser for the element type
      parsec(:type_parser),
      ignore_whitespace(sym_lbracket),
      ignore_whitespace(sym_rbracket)
    ])
    |> post_traverse({__MODULE__, :transform_list_type, []})

  # Helper for tuple type transformation
  defp transform_tuple_type(types), do: {:tuple, types}

  # Define how to parse multiple types separated by commas
  comma_separated_types =
    # Use 'repeat' and 'optional' for flexibility with trailing commas (though not strictly needed by spec)
    # More simply: times(parsec(:type_parser), min: 1) |> repeat(ignore_whitespace(sym_comma) |> parsec(:type_parser))
    # Let's use NimbleParsec's separated list helper (cleaner):
    separated_list(parsec(:type_parser), ignore_whitespace(sym_comma), min: 1)

  tuple_type =
    sequence([
      ignore_whitespace(sym_lparen),
      comma_separated_types,
      ignore_whitespace(sym_rparen)
    ])
    # The result from sequence is [[lparen, [type1, type2, ...], rparen]].
    # We only want the middle list [type1, type2, ...].
    # post_traverse gets the whole [[...]], so we pattern match inside the helper.
    |> post_traverse(fn [_lparen, types, _rparen] -> {:tuple, types} end)


  # Now, define the implementation for the main type parser
  # It chooses between the different kinds of types. Order matters if prefixes overlap!
  # List/Tuple need to come before basic_type if basic_type could be a prefix (not the case here).
  defcombinatorp :type_parser_impl,
    choice([
      list_type,
      tuple_type,
      basic_type # Fallback to basic types
    ])


  # --- Test Function ---
  defcombinatorp :test_type_parser, ignore_whitespace(parsec(:type_parser))

  def parse_type(input) do
    parse(input, :test_type_parser)
  end
end

Explanation:

  • defparsec :name, :implementation: This is how we handle recursion in NimbleParsec. We declare a parser :type_parser will exist, and define its logic in :type_parser_impl. Inside :type_parser_impl (or parsers it calls, like list_type), we can refer back to :type_parser using parsec(:type_parser).
  • list_type: Parses a Type, then [, then ]. Uses parsec(:type_parser) to handle the Type part recursively. Transforms the result [parsed_type] into {:list, [parsed_type]}.
  • separated_list(item_parser, separator_parser, min: 1): A very useful built-in combinator for parsing comma-separated (or other separator) lists. Parses at least one item_parser, followed by zero or more separator_parser and item_parser sequences.
  • tuple_type: Parses (, then a comma-separated list of types (using separated_list and parsec(:type_parser)), then ). Transforms the result [type1, type2, ...] into {:tuple, [type1, type2, ...]}.
  • :type_parser_impl: Simply chooses between the different type structures we've defined.

Step 5: Parsing Branches

A session type involves sequences or choices of actions (branches). A branch looks like Label(Payload).Continuation. We can have single branches or multiple branches within {...}.

# lib/st_parser.ex (additions)
defmodule StParser do
  # ... (previous code) ...

  # --- Session Type Structure (Recursive) ---

  # Forward declaration for the main session type parser
  defparsec :session_type, :session_type_impl

  # Helper to build the SBranch struct
  defp transform_branch([label, payload, continuation]) do
    %Maty.ST.SBranch{label: label, payload: payload, continue_as: continuation}
  end

  # Parses: Label(Payload).Continuation
  branch =
    sequence([
      # Label (Identifier)
      ignore_whitespace(identifier),
      # Payload (Type)
      ignore_whitespace(sym_lparen) |> parsec(:type_parser) |> ignore_whitespace(sym_rparen),
      # Continuation (Session Type)
      ignore_whitespace(sym_dot) |> parsec(:session_type) # Recursive!
    ])
    |> post_traverse({__MODULE__, :transform_branch, []})

  # Parses one or more branches separated by commas
  comma_separated_branches =
    separated_list(branch, ignore_whitespace(sym_comma), min: 1)

  # Parses either a single branch OR { branch1, branch2, ... }
  branches =
    choice([
      # Multi-branch case: { ... }
      sequence([
        ignore_whitespace(sym_lbrace),
        comma_separated_branches,
        ignore_whitespace(sym_rbrace)
      ])
      |> post_traverse(fn [_lbrace, branch_list, _rbrace] -> branch_list end), # Extract list

      # Single branch case: Just parse one branch and wrap it in a list
      branch |> map(fn b -> [b] end)
    ])

  # --- Test Function ---
  # We need a dummy session_type_impl for now to test branches independently
  # Let's make it just parse 'end' for testing purposes
  defcombinatorp :session_type_impl_dummy, ignore_whitespace(kw_end) |> map(fn _ -> %Maty.ST.SEnd{} end)
  defparsec :session_type_dummy, :session_type_impl_dummy

  # Test branch parser using the dummy continuation
  branch_test =
    sequence([
      ignore_whitespace(identifier),
      ignore_whitespace(sym_lparen) |> parsec(:type_parser) |> ignore_whitespace(sym_rparen),
      ignore_whitespace(sym_dot) |> parsec(:session_type_dummy) # Use dummy!
    ])
    |> post_traverse({__MODULE__, :transform_branch, []})

  comma_separated_branches_test =
    separated_list(branch_test, ignore_whitespace(sym_comma), min: 1)

  branches_test =
    choice([
      sequence([
        ignore_whitespace(sym_lbrace),
        comma_separated_branches_test,
        ignore_whitespace(sym_rbrace)
      ]) |> post_traverse(fn [_, bl, _] -> bl end),
      branch_test |> map(fn b -> [b] end)
    ])

  defcombinatorp :test_branches_parser, branches_test

  def parse_branches(input) do
    parse(input, :test_branches_parser)
  end
end

Explanation:

  • defparsec :session_type, :session_type_impl: We declare our main parser, which will handle Input, Output, and End.
  • branch: Parses the Label(Payload).Continuation sequence. Crucially, it uses parsec(:session_type) to parse the Continuation, making it recursive. It uses post_traverse to build the %Maty.ST.SBranch{} struct.
  • comma_separated_branches: Uses the separated_list helper again.
  • branches: Uses choice to handle the two cases:
    • Multi-branch ({...}): Parses {, the list of branches, then }. We use post_traverse to extract just the list of branches from the sequence result.
    • Single branch: Parses just one branch and uses map to wrap the single resulting struct in a list [...], ensuring the branches combinator always returns a list of branches.
  • Testing Hack: Since branch depends on the full session_type parser (which we haven't finished), we create temporary _test versions (branch_test, etc.) that use a dummy session_type_dummy parser (which just parses end) for isolated testing.

Step 6: Parsing Input, Output, and End

Now we define the top-level structures: Input (&Role:...), Output (+Role:...), and End (end).

# lib/st_parser.ex (additions)
defmodule StParser do
  # ... (previous code) ...

  # --- Session Type Structure (Implementation) ---

  # Helper to build SIn struct
  defp transform_input([_ampersand, role, _colon, branches_list]) do
    %Maty.ST.SIn{from: role, branches: branches_list}
  end

  input_type =
    sequence([
      ignore_whitespace(sym_ampersand),
      ignore_whitespace(identifier), # Role
      ignore_whitespace(sym_colon),
      branches # Use the branches parser from Step 5
    ])
    |> post_traverse({__MODULE__, :transform_input, []})

  # Helper to build SOut struct
  defp transform_output([_plus, role, _colon, branches_list]) do
    %Maty.ST.SOut{to: role, branches: branches_list}
  end

  output_type =
    sequence([
      ignore_whitespace(sym_plus),
      ignore_whitespace(identifier), # Role
      ignore_whitespace(sym_colon),
      branches # Use the branches parser from Step 5
    ])
    |> post_traverse({__MODULE__, :transform_output, []})

  # Helper to build SEnd struct
  defp transform_end(_end_keyword) do
    %Maty.ST.SEnd{}
  end

  end_type =
    ignore_whitespace(kw_end)
    |> map({__MODULE__, :transform_end, []}) # Use map as output is simple

  # --- Define the main session_type_impl ---
  # This ties everything together
  defcombinatorp :session_type_impl,
    choice([
      input_type,
      output_type,
      end_type
    ])

  # --- Top-Level Parse Function ---
  defparsecp :st_parser, parsec(:session_type) |> eos() # Ensure entire input is consumed

  @doc """
  Parses a Session Type string into Maty.ST structs.
  """
  def parse(input) when is_binary(input) do
    case NimbleParsec.parse(input, :st_parser) do
      {:ok, [result], "", _, _, _} -> {:ok, result}
      {:ok, _, rest, _, {line, col}, _} -> {:error, "Unexpected input remaining at #{line}:#{col}", rest}
      {:error, reason, rest, _, {line, col}, _} -> {:error, "Parse error at #{line}:#{col}: #{reason}", rest}
      other -> {:error, "Unknown parse result", other} # Should not happen
    end
  end
end

Explanation:

  • input_type: Parses &, Role (identifier), :, then the branches. Uses post_traverse to build %Maty.ST.SIn{}.
  • output_type: Parses +, Role (identifier), :, then the branches. Uses post_traverse to build %Maty.ST.SOut{}.
  • end_type: Parses the end keyword. Uses map (simpler than post_traverse for single results) to create %Maty.ST.SEnd{}.
  • :session_type_impl: This is the real implementation now! It uses choice to try parsing an input_type, output_type, or end_type.
  • eos(): Stands for "end of stream". Appending this ensures that the parser only succeeds if it consumes the entire input string. This prevents partial parses.
  • parse/1: Our main public function. It runs the :st_parser (which uses :session_type recursively and checks for eos()) and provides cleaner success/error tuple formats.

Conclusion & Next Steps

We've successfully built a parser step-by-step using NimbleParsec's combinator approach. We saw how to:

  • Define basic token parsers (string, ascii_char).
  • Combine parsers using sequence, choice, repeat.
  • Handle whitespace using ignore.
  • Transform parsed data using map, reduce, and post_traverse.
  • Implement recursive parsers using defparsec.
  • Ensure full input consumption using eos().
  • Test incrementally at each stage.

From here, you could:

  • Add More Robust Error Handling: NimbleParsec offers ways to provide more context or custom error messages.
  • Extend the Grammar: Add support for more complex types or different constructs if needed.
  • Integrate: Use this parser within a larger Elixir application that deals with communication protocols.
  • Write More Tests: Create a comprehensive test suite using ExUnit to cover edge cases.

Hopefully, this walkthrough has demystified parser combinators a bit and shown how you can build powerful parsers directly within your Elixir code. Happy parsing!
